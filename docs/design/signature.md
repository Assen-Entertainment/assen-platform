# 하츠코이 시그니처 디자인 v1.1 — "밋밋함"의 해법

**16개 플랫폼**(4개 카테고리: F&B·레트로 / 게임·수집형 / 캐릭터 IP·서브컬처 / 콘카페 — @home·메이드리밍을 분리하면 17개)을 "성격 → 구현 장치"로 분해한 결과. 전체 출처·검증 메모(적대적 검증 REFUTED 0건, 부분 검증·추정 표기 포함)는 `.omc/autoresearch/hatsukoi-design-signature/runs/run-20260611/research-sources.md`에 실재하며, 아래 표에는 행별 대표 출처를 직접 표기한다.

## 0. 진단 — 왜 밋밋한가

현재 28화면은 토큰·컴포넌트 차원에서 정합하지만 "일반적인 라이트 파스텔 앱"이다. 분해 결과의 결론: **개성은 컬러가 아니라 ①명명(어휘) ②한두 문턱의 연출 ③실패의 처리에서 나온다.** 16개 플랫폼 전부가 이 세 층위에서 성격을 구현했고, 우리는 세 층위가 전부 표준값이다.

## 2. 하츠코이 시그니처 3+2 (구체 스펙)

### S1. 「두근」 시스템 — 첫사랑 어휘 전면 치환 (명명이 1차 디자인)
- 포인트 → **두근** ("두근 +50"), 예약 → **약속**, 방문 기록 → **만난 날**, 체키 앨범 → **추억**, 위시 → **마음에 담아두기**
- 호칭은 표준 존대 유지(큐어메이드 이중 구조: 어휘는 세계관, 호칭은 격식) — 닉네임 호명 없음
- 카피 규약: 평소 건조한 정보체, **완료 모먼트 한 곳만 들뜸 허용**("예약됐어요!"), 빈/실패 상태는 누적 축하형·시스템 사과 어법("이번엔 준비하지 못했어요"), 마감·손실·죄책감 어휘 금지
- 적용 위치: 전 화면 카피 + F3(두근 내역) + B2/D2 토스트. 공수: 카피 시트 1장 + setText 일괄

### S2. 모션 토큰 3종 — 연출은 두 문턱에만 (토스 교훈: 스펙이 시그니처를 만든다)
| 토큰 | 스펙 | 적용 |
|---|---|---|
| `signature.heartConfirm` | 크림 플래시 80ms → 하트 윤곽 스트로크 드로잉 250ms → 차임 1음+햅틱 1펄스 (~400ms) | 체크인(B1→B2), 예약 확정, 가입 완료 — 전 완료 모먼트 공통 |
| `signature.filmDevelop` | 배출 400ms(오버슈트) → 불투명도 현상 1.2–1.8s(햅틱 틱 2회) → 도장음 | 체키 획득. 등급 텔=필름 테두리 파스텔색. 첫 획득만 풀 연출, 재획득은 탭 스킵 |
| `signature.stampThunk` | 도장 하강 → 눌림(잉크 번짐 1프레임) → 카드 2px 출렁 → 정착 (~350ms) + '쿵' 사운드 1개 | 스탬프 적립, 도감 등록 |
- **tokens.md 정합**: 기존 motion 스케일(short~long 450ms)은 일반 전환용으로 **유지**하고, 채택 시 `motion.signature.*` 네임스페이스로 위 3종을 **추가**한다. 기존 "long 450ms = 체키 획득·스탬프 연출" 정의는 signature 토큰으로 **대체**되므로 해당 설명문만 삭제 (토큰 값 변경 없음)
- **easing 바인딩**: `heartConfirm`·`filmDevelop`의 등장 구간 = 기존 `easing.celebrate`(0.05,0.7,0.1,1), `stampThunk` = `easing.standard`(0.2,0,0,1), filmDevelop의 현상 구간은 linear 불투명도. 오버슈트 수치는 구현 시 celebrate 커브가 내장
- 원칙: 이 3개 외 화면 전환은 표준 모션 — **대비가 시그니처를 만든다** (디즈니: 입장 한 곳에 예산 집중). 사운드 자산 2종('쿵', 차임)은 채택 후 제작 발주
- 그라디언트·발광 금지와 호환 (불투명도·물리 모션만)

### S3. 성냥갑 티켓 양식 + 크림소다 3색 규칙 (준킷사 문법)
- 티켓/쿠폰/체키권 템플릿: 세로 직사각 + 1px 솔리드 테두리 프레임 + 점포 로고타입 + **발행 No.**(4자리) — 수집 의식과 직결
- 컬러 서사: 크림(베이스) + 시즌 파스텔 1색(소다) + **체리 도트**(알림·완료 마크 전용)
- **체리 토큰 정의(채택 시 tokens.md 반영)**: 신규 색이 아니라 기존 `red.main`(#B64650)의 **별칭 `decorative.cherry`**로 정의. error와의 구분은 형태 규칙으로 강제 — **error는 반드시 면(red.bg)+문구를 동반**, **cherry는 8px 단독 도트/완료 마크 한정**(면·문구 금지). CountBadge가 cherry의 유일한 기존 소비자
- 적용: CouponTicketSet·EntryTicket 템플릿 개편 + CountBadge 의미 재정의. 공수: 컴포넌트 2종 수정 + 토큰 별칭 1행

### S4. 방문 후 「오늘의 기록」 reveal (포켓몬 슬립 — 보상은 돌아본 순간에)
- 방문일 다음 앱 오픈 1회 한정, 고정 순서 3카드: ①오늘 날짜 타이포 카드 → ②두근 카운트업 → ③오늘의 스탬프 도감 등록(희귀도 별)
- 세계관 논리: 첫사랑은 '집에 와서 곱씹는 밤'에 완성된다. 과몰입 푸시 없이 재방문 리듬 생성
- 적용: 신규 화면 1종(B3) + 주간 마디("이번 주의 첫 페이지") 카드. 데이터 모델 영향 — ASS-84 범위 검토 연계

### S5. 엇갈림의 처리 (치이카와+TDR — 실패를 숨기지 않는다)
- 품절·마감·낙선: 회색 비활성 대신 **기울어진 하트 윤곽(-8°) + 카피 "다음엔 꼭 만나요"**(고정 문구)
- 당첨/낙선 어법 분리: 선언형("자리가 마련됐어요") / 시스템 사과형("이번엔 준비하지 못했어요")
- 적용: EmptyState(문구 교체)·TimeSlotChip full(하트 마크 추가)·이벤트 낙선 상태(신규 variant). 첫사랑의 '아쉬움'은 정서 자산

## 3. 보조 적용안 (우선순위 라벨: 지금=Figma 즉시 / P0-후반=화면·카피 확정 단계 / P1=데이터 모델 필요)

6. **[P0-후반] 성장하는 회원증** (산리오 번안): MembershipCard의 strip 모티프가 방문 누적으로 변형(하트 윤곽→점선 채움→실선→이중) — `strawberry/border→ink` 기존 스텝만 사용, 등급 배지 불요. 적용: MembershipCard variants 확장. 세계관: 관계가 깊어지는 과정을 도형 변화로
7. **[P1] 학사일정 4시즌** (스타벅스): 입학식(봄)·여름방학·문화제(가을)·졸업식(겨울). 시즌당 **sys.seasonAccent 슬롯 1개**에 기존 파스텔 hue를 재배정(신규 색 없음 — strawberry→sky→lemon→lavender 순환)+스탬프 도형 1종 교체. 코스터→체키 티켓→앱 3표면 동기화, 시즌 첫날="개학일". 세계관: 학교 달력이 곧 하츠코이의 달력
8. **[P1] 스탬프 도감 + 희귀도** (포켓몬 슬립): 요일·계절·이벤트별 변형 기하 스탬프, 별 1~3. 적용: StampCard 슬롯 도형 변형 + CollectionCell 재사용. 데이터 모델 영향 — ASS-84 연계. 세계관: 그날의 우연이 무엇을 남기는가
9. **[지금] '오늘의 이름표'** (LBM): 체크인 시 학교 명찰형 태그(학년-반 칸 양식, 타이포만). 적용: 신규 molecule `NameTag` — B2 화면에 배치. 세계관: 같은 반이 된 첫날의 명찰 — 매 방문이 '다시 만난 첫날'
10. **[지금] 한 글자 타이포 장치** (P5): display/headline 사용처에서 타이틀 한 글자만 손글씨체+파스텔 스티커 사각. 적용: 텍스트 스타일 사용 규칙(서체 확정 후). 세계관: 또박또박 쓴 편지에서 한 글자만 삐져나온 설렘 — 절제된 화면에 새는 감정의 표식
11. **[규범] 하지 않는 것 목록** (큐어메이드): 닉네임 호명·답장 보장·푸시 조르기·과한 이모지 금지 — *화면 적용안이 아니라 브랜드 규범*. S1 카피 규약과 함께 카피 가이드 문서에 수록 (적용안 카운트에서 제외)
