## 1. 현재 개인정보 처리 실태 (코드 기준·결정의 전제)

최소수집 설계가 이미 코드에 반영되어 있어, 아래 결정은 그 위에 얹힌다.

- **전화번호**: 원본 **미저장**. HMAC-SHA256 가명해시(`Account.auth_subject_hash`, 전용키 `PHONE_IDENTIFIER_HMAC_KEY`)만 저장 → 역산 불가. (ASS-287 A-2 완료)
- **생년월일/주민번호/CI·DI**: **미저장**. KYC는 성인여부(bool)·상태 플래그만 파생 저장.
- **닉네임**: 평문(표시용).
- **이메일**: **수집 필드 없음**. (※ 현행 web `/policy/privacy` placeholder가 "이메일 수집"이라 오기 → §7에서 정정 대상)
- **배송지**: `ENABLE_SHIPPING_CHECKOUT=False`(base/prod) → 수집 경로 503 차단, **0건 저장**.
- **동의**: `ConsentRecord`(kind∈{rule,privacy,terms,marketing,age} + version + 시각), 버전드, gate로 강제. 문구만 미정.
- **결제**: mock txn(opaque)만. 카드/PII 0. 실 PG는 게이트 뒤.
- **토큰**: SHA-256 해시만 저장, 즉시 폐기 가능.

## 2. 개인정보 보유·파기 스케줄 (D2·D3·D6 반영)

> 원칙: **목적 달성 시 지체 없이 파기**(PIPA §21). 법령 의무분만 예외적으로 기간 보존하되, **가능한 한 익명화/분리보관**한다.

| 데이터 | 항목 | 보유 기간 | 파기·처리 방식 | 법적 근거 |
|---|---|---|---|---|
| 회원 식별·인증 | 전화 HMAC 해시·닉네임·auth_method·KYC 상태 | **탈퇴 시까지** → 탈퇴 즉시 익명화 | 탈퇴 이벤트 시 동기 익명화(§3) | PIPA §21 목적달성 파기 |
| 동의 기록 | ConsentRecord(kind/version/시각) | 탈퇴 후 관련 거래 보존기간 종료 시까지(익명화된 계정에 부착) | 계정 파기 배치와 함께 파기 | 처리내역 입증 |
| **거래·계약·청약철회** | 주문·결제·청약철회 기록(실 PG 도입 후) | **5년** | 5년 경과분 배치 파기 | 전자상거래법 시행령 §6① |
| **대금결제·재화공급** | 결제수단·공급 기록(배송 도입 후) | **5년** | 상동 | 전자상거래법 시행령 §6① |
| **소비자 불만·분쟁** | 신고(safety)·환불·분쟁 처리 기록 | **3년** | 3년 경과분 배치 파기 | 전자상거래법 시행령 §6① |
| 접속·보안 로그 | 로그인 IP·요청 ID·인증 이벤트 | **3개월** | 3개월 경과분 배치 파기 | 보안·감사(최소 보관, D6) |
| 인증 토큰 | access/refresh 해시 | 만료 즉시 무효 | 만료분 주기 파기 | — |
| 익명 세션 | AnonymousSession(미병합) | 1년(권장 기본) | 미병합 1년 경과분 파기 | 최소보관 |

> ★ **현 시점 유의**: 실 PG/배송이 mock/차단 상태라 **실 거래 PII가 아직 없다**. 위 5년/3년은 실결제·실배송 활성화 시점부터 적용되며, mock 주문은 비개인정보로 자유 파기 가능. 배송(D1 보류)은 수집 자체가 없어 재화공급 5년 대상 데이터가 v1엔 발생하지 않는다.

## 3. 탈퇴 · 익명화 처리 정책 (D3)

**트리거**: 팬 탈퇴 요청(신규 `POST /api/account/withdraw` 필요 — 현재 미구현).

**즉시(동기) 처리**:
1. `Account.nickname` → `""`, `auth_subject_hash` → `""`(전화 해시 제거 → 재가입 시 신규 계정), `is_active=False`, `withdrawn_at` 기록.
2. 인증 토큰 패밀리 전량 revoke(즉시 로그아웃).
3. 동의 기록: 익명화된 계정에 부착 유지(PII 아님) → 계정 파기 배치 시 함께 삭제.
4. 마케팅 수신 상태 즉시 해제.

**분리 보존(법정 의무분)**:
- 거래·결제·분쟁 기록은 **익명화된 fan_id(가명 토큰)** 로만 연결 유지, 위 §2 기간(5년/3년) 동안 보존 후 파기.
- 이 기록에는 배송 PII·이름·전화가 포함되지 않음(D1 보류 + 최소수집).

**재가입**: 전화 해시가 제거되므로 동일 번호로 신규 계정 생성 가능(uniq 제약 위반 없음).

**파기 실행**: 탈퇴 즉시 익명화는 **동기**, 법정 보존기간 만료 파기는 **야간 배치**(retention sweeper) + 접속로그 3개월 파기도 동일 배치.

## 4. 우편체키 / 배송 = 보류 확정 (D1)

- `ENABLE_SHIPPING_CHECKOUT`는 base/prod/demo **하드 False 유지**. 굿즈/배송 상품 결제 시 `503 SHIPPING_CHECKOUT_UNAVAILABLE` → **수령인 이름/전화/주소 0수집**(ASS-287 A-1 완료 상태 그대로).
- v1 판매 대상 = **디지털 콘텐츠·멤버십·무료 획득**(+ 카페 오프라인 체키 기록은 operator 스코프로 이미 존재, PII·이미지 미저장).
- 실물 우편체키 판매는 **수요 검증 후 별도 웨이브**: 그때 (a) 배송 PII 수집·§2 재화공급 5년 보존, (b) 택배사 제3자 제공 동의 문구, (c) `ENABLE_SHIPPING_CHECKOUT` 개방을 **다시 승인 게이트**로 다룬다.

```

1. 수집 항목
   - 필수: 휴대전화번호(가명처리된 해시값으로만 보관), 닉네임, 인증수단 정보
```

## 6. 구현 플랜 (게이트 무관 엔지니어링 — 대표 방향 확정분)

아래는 **새 의사결정 게이트를 열지 않는다**(프라이버시 통제 강화·데이터 최소화 방향). 실 PII 수집을 여는 flag(배송·실 PG)는 계속 닫힘.

1. **가입 14세 게이트 (D5)**: 가입 플로우에 "만 14세 이상" 필수 확인 + 서버 검증. 14세 미만 차단.
2. **탈퇴 API + 즉시 익명화 (D3)**: `POST /api/account/withdraw` — 닉네임/전화해시 제거·토큰 revoke·마케팅 해제·`withdrawn_at` 기록. 거래/분쟁 기록은 가명 유지.
3. **보유기간 파기 배치 (D2·D6)**: 야간 retention sweeper — 접속로그 3개월 경과분, 법정 보존기간(5년/3년) 만료분, 미병합 익명세션 1년 경과분 파기.
4. **마케팅 채널별 동의 (D8)**: `marketing` 동의를 채널(push/sms/email)별로 기록·조회·철회. 발송 로직이 채널 동의 확인.
5. **consent 문구·버전 배선 (D4)** ✅: 확정 문구를 `2026-07-12-v1`로 상수화(draft 제거), 가입/성인 게이트가 현재 버전 동의를 요구. 문구 변경 시 버전 상향 → 재동의.
6. **web `/policy/*` 정정 (§7)**: privacy placeholder의 오기(이메일·결제정보 수집) → 실제 수집 항목(전화 해시·닉네임)으로 교체, §5 초안 반영.

> 착수 순서 권장: 1·6(단순·즉효) → 2·4 → 3(배치). 각 단계 pytest/vitest + code-review, flag는 불변.
