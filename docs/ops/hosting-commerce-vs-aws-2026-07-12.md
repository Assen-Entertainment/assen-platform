# 인프라 방향 재검토 — 호스팅 커머스(Cafe24/아임웹/식스샵) vs 커스텀 AWS (2026-07-12)

대표 제안("AWS뿐 아니라 Cafe24 같은 쇼핑몰 호스팅도 고려")에 따라 국내 호스팅 커머스를 조사하고, Assen 인프라 방향을 재추천한다. (조사=웹, 2026-07 기준. 요금·정책은 변동 가능.)

## 1. 조사 결과 (5개 질문)

### ① 크리에이터별 정산/수익배분 — ★핵심 한계
- **세 플랫폼(Cafe24·아임웹·식스샵) 모두 본질적으로 "단일 판매자(브랜드) 쇼핑몰"** 이다. **여러 크리에이터가 각자 판매하고 크리에이터별로 정산·수익배분하는 마켓플레이스 모델은 기본 미지원.**
- Cafe24의 "마켓플러스/셀러허브"는 **내 상품을 네이버·쿠팡 등 외부 오픈마켓에 뿌리는** 채널 통합 도구지, **내부 다중 크리에이터 정산이 아니다.** "제휴 프로그램 정산"은 어필리에이트용.
- **결론**: 호스팅 커머스를 쓸 경우 **Assen(회사)이 단일 판매자가 되고, 크리에이터 수익배분은 Assen이 자체 원장으로 처리**해야 한다(이미 provenance/PaymentAttempt 원장 구축됨).

### ② 구독/멤버십·디지털 콘텐츠
- **정기결제(구독)**: Cafe24 = 업계 최초로 쇼핑몰 솔루션에 정기결제 내장(이니시스 연동, 카드 주기 결제). 식스샵·아임웹도 정기결제 지원.
- **디지털 다운로드 상품**: Cafe24·아임웹 모두 디지털/다운로드 상품 판매 지원(미디어·자료 파일 등).
- **한계**: "멤버십 등급별 게이팅 콘텐츠 피드"(팬플랫폼형)는 네이티브 개념이 아님 — 정기결제 상품으로 모델링은 가능하나, 등급별 접근권한이 있는 콘텐츠 피드/커뮤니티는 쇼핑몰 틀 밖.

### ③ 헤드리스 API 연동 한계
- Cafe24 = 국내 최대 오픈 REST API(Admin/Front API, OAuth 2.0) + 앱스토어(440+ 앱). **헤드리스로 커머스 백엔드 활용 가능**하나, API가 **쇼핑몰 모델(상품/주문/회원/배송) 중심**이라 팬플랫폼 고유 도메인은 커버 안 됨. 레이트리밋 등 상세는 실 연동 스파이크로 확인 필요.
- 아임웹·식스샵은 API가 Cafe24보다 제한적(디자인/올인원 지향).

### ④ 수수료·요금 (2025 기준, VAT 별도·변동 가능)
| | 이용료 | 판매(서비스) 수수료 | PG(카드) 수수료 | 비고 |
|---|---|---|---|---|
| **Cafe24 PRO** | **호스팅 무료** | 브랜드몰 2~3% / 마켓 1% | ~1.8~3.3% | PG 가입비 20만(카페24페이먼츠 무료), 정산한도 1천만까지 보증보험 무료 |
| **아임웹** | 월 ~3만(연할인 시 ~2.4만) | **없음**(PG만) | ~1.8~3.3% | 디자인/비주얼 강점. **레퍼런스 madeyou.kr이 사용** |
| **식스샵 프로** | 월 ~3만(연할인 시 ~2.2만) | 없음(PG만) | ~1.9~3.4% | 크리에이터/작가 D2C 친화, 정산 500만↓ 보증보험 무료 |

→ PG 수수료는 셋 다 대동소이(~2~3.4%). 차이는 **이용료 구조**(Cafe24 무료+판매수수료 vs 아임웹/식스샵 월정액+판매수수료 0)와 **성격**.

### ⑤ 플랫폼 성격 비교
- **Cafe24**: 규모/플랫폼 구축·최대 API·무료 호스팅. 커스텀 연동·확장에 유리.
- **아임웹**: 디자인/브랜딩 우선, 1인·소규모 비주얼 상품. **서브컬쳐 통판 레퍼런스(madeyou.kr) 실사용**.
- **식스샵**: 작가/크리에이터 D2C, 심플·브랜딩. 소규모 크리에이터몰.

## 2. 핵심 판정
- **호스팅 커머스가 대신 풀어주는 것**: 결제(PG)·배송·정산(단일판매자)·회원·정기결제·디지털상품·호스팅 → **대표 요청 문서의 A(AWS 인프라 상당수)·B-1/3/5/6(결제·SMS·스토리지·이메일)·배송을 상당 부분 제거.**
- **호스팅 커머스가 못 하는 것**: **다중 크리에이터 마켓플레이스 정산 · 멤버십 게이팅 콘텐츠 피드 · 커뮤니티/스튜디오** = 팬플랫폼 고유 영역 → 여전히 커스텀 필요.

## 3. 인프라 재추천 — 하이브리드(권장)
> "AWS를 다 짓기 전"인 지금이 방향 전환의 최적기다.

**커머스(굿즈·체키·통판·결제·배송) = 호스팅 커머스에 얹기** + **팬플랫폼(멤버십·콘텐츠·피드·크리에이터) = 커스텀 유지**.

- **효과**: E10(AWS ECS/RDS/배포 풀스택)·실 PG/배송/스토리지 계약 부담이 커머스에 한해 대부분 사라짐 → **출시 속도↑, 초기 빌드/운영비↓, 리스크↓.** 커스텀 팬플랫폼은 가벼워져 저비용 호스팅으로도 가능.
- **크리에이터 정산**: Assen이 단일 판매자, 수익배분은 자체 원장(이미 구축).
- **연동 모델**: ①헤드리스(호스팅몰을 API 커머스 백엔드로) 또는 ②병행몰(굿즈몰 별도 + 플랫폼서 링크, 가장 빠름).

**플랫폼 선택 가이드**:
- **아임웹** — 레퍼런스(서브컬쳐 통판)가 이미 씀, 디자인·속도, 판매수수료 0. **초기 굿즈몰 최단 경로**.
- **Cafe24** — 최대 API·무료 호스팅·확장/헤드리스. **커스텀 플랫폼과 깊게 API 연동**하거나 규모 확장 시. (assenent.com 이미 Cafe24 물려 있음.)
- **식스샵** — 가장 작은 크리에이터 D2C.

## 4. 단계 제안
1. **지금(스파이크·저비용)**: 굿즈/체키 판매를 **아임웹 또는 Cafe24** 병행몰로 개시 → 결제·배송·정산 즉시 확보(실 PG/배송 계약을 호스팅사가 대행). 커스텀 커머스(Django 목) 활성화를 **보류/대체 검토**.
2. **팬플랫폼은 커스텀 유지·경량화**: 멤버십·콘텐츠·피드. AWS 풀스택 대신 필요한 만큼만.
3. **깊은 연동이 필요해지면**: Cafe24 헤드리스 API로 커머스↔플랫폼 통합.

## 5. 검증 필요(결정 전 스파이크)
- 헤드리스로 **커스텀 프런트 + 호스팅몰 커머스** 실연동 가능 범위/레이트리밋(Cafe24 API 실측).
- **멤버십/구독 상품 + 디지털 콘텐츠 게이팅**을 호스팅몰 정기결제로 어디까지 표현 가능한지.
- **크리에이터 정산**을 단일판매자 모델 + 자체 원장으로 처리 시 세무/전자상거래 통신판매 신고 영향(법무).
- 우리 카테고리에서 아임웹 vs Cafe24 실사용 비교(레퍼런스 madeyou.kr = 아임웹).

## 결론
**"커스텀 AWS로 커머스까지 다 짓기"는 현 단계에 과투자일 수 있다.** 커머스는 **호스팅 커머스(아임웹/Cafe24)로 얹고**, 팬플랫폼만 커스텀 유지하는 **하이브리드**가 비용·속도·리스크에서 유리하며, 레퍼런스도 이 길이다. 단 **다중 크리에이터 정산·멤버십 콘텐츠는 어느 호스팅도 대신 못 하므로** 그 부분은 커스텀으로 남는다. 최종 선택은 "**Assen을 다중 크리에이터 마켓플레이스로 볼지, 단일 브랜드(회사)가 굿즈+팬사이트를 운영하는 형태로 볼지**"에 달려 있다 — 이는 대표 전략 결정.
